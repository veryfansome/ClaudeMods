# evolve:round — one generation

`evolve/EVOLVE.md` in the project is the manual; this skill is the entry point plus the decisions that are easy to get wrong. The `evolve` CLI (on PATH) is the decision-maker: parent selection, guards, dedup, budgets, and the final-split firewall are its calls, not yours — you orchestrate inventors and relay its verdicts.

## The round

1. **Re-ground.** `evolve board`; read `evolve/insights.md`. If `evolve sample` exits 3, the budget is spent or the search is stale — report and stop (this is the /loop stop condition; end the loop rather than overriding the engine).
2. **Sample.** `evolve sample --k <N> --seed <round-tag>` — one slot per inventor: parent, operator (diff/rewrite/cross + partner), inspirations. The engine's weighted sampling deliberately does NOT always pick the champion; respect its choice — the offspring penalty is what keeps the search from tunnel-visioning one lineage.
3. **Brief + dispatch.** `evolve brief --operator <op> --parent <id> --seed <slot seed from sample> [--axis <axis>] [--cross-with <id>]` per slot — pass the slot's own `seed` (from `sample`'s output) so each inventor gets that slot's inspirations, and `--axis` is REQUIRED in registry mode. That context block is the inventor's whole grounding — pass it verbatim. Dispatch inventors as parallel subagents via the Workflow tool with `effort: 'high'` (effort is load-bearing: low-effort inventors produce safe tweaks that waste eval budget) and, in markers mode, `isolation: 'worktree'` so each edits its own copy. If the Workflow tool is unavailable, fall back to sequential Agent-tool dispatch — same briefs, same rules. For genuine model diversity, external CLI inventors (run read-only, output captured) may be added on the identical brief. Require each inventor to return a structured proposal: name, one-line rationale, the risk it sees, and its edit (markers: edits in its worktree; registry: one complete impl module honoring the baseline's contract).
4. **Guard, then Reflexion.** Registry proposals: write each impl into `evolve/chunks/<axis>/` yourself and smoke-test the module in isolation before spending an eval (imports, obvious contract conformance) — inventors can't test against the live harness, so harden their integration bugs rather than discarding good ideas. All proposals: `evolve guard` first; on violation or a later dedup rejection (exit 4/5), re-brief the SAME inventor once with the engine's reason verbatim ("code outside markers changed"; "0.97 similar to X — differ mechanistically"), then drop the slot.
5. **Score at proxy.** Per survivor, supply the candidate source — markers: `--candidate <worktree>` (its own worktree) or `--patch <file>`; registry: write the impl into `evolve/chunks/<axis>/` and pass `--genome <file>`. Full form: `evolve score --mode proxy --candidate <wt> --id <id> --parent <p> --inventor <who> --operator <op> --rationale "<one line>"`, serialized if the eval contends for resources. Failures record with reasons — that is signal, not mess; never delete records.
6. **Promote.** Only proxy wins clearing `champion + noise_floor` earn a full run. If the eval is noisy (nonzero floor), first `evolve rescore --id <champion> --mode proxy` back-to-back with the challenger and compare that paired delta — environment drift masquerades as fitness. Then promote the challenger with `evolve rescore --id <challenger> --mode full` (rescore replays the archived candidate under the new budget, reusing its id — so promotion, paired reruns, and final validation never trip the dedup gate). Trust only full-budget results; expect proxy→full shrinkage.
7. **Recombine.** After single-axis wins, stack them (registry: one genome carrying each axis's winner; markers: a cross-operator slot next round) and score the combination at full. Epistasis cuts both ways — the stack can beat or lose to its parts; test, never assume. Failed traits may be retried recombined in a changed context.
8. **Record + report.** Roughly every `search.insights_interval` generations (watch `board`'s generation count — there is no engine-side timer), distill the archive's recent records into `evolve/insights.md`: ≤5 recommendations, numbers not verdicts (editorializing biases the next round; negatives carry the same weight as wins). Report to the user: slots dispatched, guard/dedup rejections with reasons (these are session-local — the engine does not archive them, so surface them here), proxy scores vs floor, promotions, the new board line.

## Don't get these wrong

- **Never score `--split final` for selection.** The final split exists to validate a promoted champion, once, before external claims. The engine firewalls those records out of sampling; don't route around it.
- **Never hand inventors the eval.** The brief is their whole context — do not add the adapter, the metric internals, or `archive/private/` to it. If an inventor edits a protected path, that candidate is dead regardless of its score.
- **Proxy deltas under the noise floor are noise.** Don't burn a full run on one, and don't celebrate one to the user.
- **Serialize resource-contended evals.** One scoring queue via tracked background tasks, not detached `&` (which loses tracking) and not long foreground commands (which time out).
- **Remote scoring** comes back via `evolve ingest --env <tag>`; scores compare only within one environment — re-baseline the champion when moving environments.

## Unattended rounds

`/loop <interval> /evolve:round` runs generations unattended. Keep the inner loop on proxy, promote sparingly, and let `evolve sample`'s exit-3 (budget/staleness) end the loop. Note exit 6 (infrastructure failure — export/dependency setup) is NOT a candidate failure and is not archived; retry rather than treating it as a dead candidate. Before claiming any improvement to the user, validate the champion once on the final split (if configured) with `evolve rescore --id <champion> --mode full --split final` and record the result as a neutral stat.
