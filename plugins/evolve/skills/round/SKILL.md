# evolve:round — one generation

`evolve/EVOLVE.md` in the project is the manual; this skill is the entry point plus the decisions that are easy to get wrong. The `evolve` CLI (on PATH) is the decision-maker: parent selection, guards, dedup, budgets, and the final-split firewall are its calls, not yours — you orchestrate inventors and relay its verdicts.

## The round

1. **Re-ground.** `evolve board`; read `evolve/insights.md`. If `evolve sample` exits 3, the budget is spent or the search is stale — report and stop (this is the /loop stop condition; end the loop rather than overriding the engine).
2. **Pre-register the gates (before scoring anything).** Decide, and commit, what would make *this* round a win — while you still can't see the results. `evolve preregister --round <tag> --g2 "<the round's objective, one line>" [--g2-threshold <n>] [--g3 "<advisory metric>"]`. This writes an immutable manifest and auto-derives **G1**, the sacred fitness-non-regression floor (`champion − noise_floor`). Promotion later requires **G1 ∧ G2**: G1 is the immovable rail (a candidate that improves the objective but regresses primary fitness past the noise floor does NOT promote); G2 is this round's actual objective; G3 is advisory only (never sufficient, never necessary). This is the discipline that lets a striking-but-false proxy win be rejected on numbers fixed in advance instead of rationalized after the fact. (Skip only for a pure free-exploration round with no promotion intent.)
3. **Sample.** `evolve sample --k <N> --seed <round-tag>` — one slot per inventor: parent, operator (diff/rewrite/cross + partner), inspirations. The engine's weighted sampling deliberately does NOT always pick the champion; respect its choice — the offspring penalty is what keeps the search from tunnel-visioning one lineage.
4. **Brief + dispatch.** `evolve brief --operator <op> --parent <id> --seed <slot seed from sample> [--axis <axis>] [--cross-with <id>]` per slot — pass the slot's own `seed` (from `sample`'s output) so each inventor gets that slot's inspirations, and `--axis` is REQUIRED in registry mode. That context block is the inventor's whole grounding — pass it verbatim. Dispatch inventors as parallel subagents via the Workflow tool with `effort: 'high'` (effort is load-bearing: low-effort inventors produce safe tweaks that waste eval budget) and, in markers mode, `isolation: 'worktree'` so each edits its own copy. If the Workflow tool is unavailable, fall back to sequential Agent-tool dispatch — same briefs, same rules. For genuine model diversity, external CLI inventors (run read-only, output captured) may be added on the identical brief. Require each inventor to return a structured proposal: name, one-line rationale, the risk it sees, and its edit (markers: edits in its worktree; registry: one complete impl module honoring the baseline's contract).
5. **Guard, then Reflexion.** Registry proposals: write each impl into `evolve/chunks/<axis>/` yourself and smoke-test the module in isolation before spending an eval (imports, obvious contract conformance) — inventors can't test against the live harness, so harden their integration bugs rather than discarding good ideas. All proposals: `evolve guard` first; on violation or a later dedup rejection (exit 4/5), re-brief the SAME inventor once with the engine's reason verbatim ("code outside markers changed"; "0.97 similar to X — differ mechanistically"), then drop the slot.
6. **Screen at proxy — the screen decides *spending*, not winning.** Per survivor, supply the candidate source — markers: `--candidate <worktree>` (its own worktree) or `--patch <file>`; registry: write the impl into `evolve/chunks/<axis>/` and pass `--genome <file>`. Full form: `evolve score --mode proxy --candidate <wt> --id <id> --parent <p> --inventor <who> --operator <op> --rationale "<one line>"`, serialized if the eval contends for resources. Spend a full run only on a candidate that clears the same-round champion proxy re-sample by more than the noise floor AND moves the round objective at proxy. **The proxy never promotes** — proxy→full can shrink *or invert* (a real search saw a proxy planning metric jump 0.011→0.286 that went 0/3 negative at full budget), and the direction isn't consistent across candidate families. Failures record with reasons — that is signal, not mess; never delete records.
7. **Promote on G1 ∧ G2, at full budget.** For a proxy winner: if the eval is noisy, first `evolve rescore --id <champion> --mode proxy` back-to-back with the challenger and compare that *paired* delta (environment drift masquerades as fitness). Then run it at full budget: `evolve rescore --id <challenger> --mode full` (rescore replays the archived candidate under the new budget, reusing its id, so it never trips dedup). Now check the gates against the full result: `evolve gate --round <tag> --id <challenger>` decides **G1** for you (the sacred fitness floor — engine-checked); you judge **G2** (the round objective) from the candidate's public metrics / text_feedback. Promote only if **G1 ∧ G2** hold. A candidate that moves G2 but fails G1 does not promote, however exciting — say so plainly. Trust only full-budget results; expect proxy→full shrinkage.
8. **Recombine.** After single-axis wins, stack them (registry: one genome carrying each axis's winner; markers: a cross-operator slot next round) and score the combination at full. Epistasis cuts both ways — the stack can beat or lose to its parts; test, never assume. Failed traits may be retried recombined in a changed context.
9. **Record + report — a no-promotion round is a first-class result.** Roughly every `search.insights_interval` generations (watch `board`'s generation count — there is no engine-side timer), distill the archive's recent records into `evolve/insights.md`: ≤5 recommendations, numbers not verdicts (editorializing biases the next round; negatives carry the same weight as wins). **A round that promotes nothing still closes with a result**: the pre-registered gates held, the champion stands, and the measured trade-off frontier (what moved, what didn't) is the round's deliverable — record it, don't treat it as a failed round. Report to the user: slots dispatched, guard/dedup rejections with reasons (these are session-local — the engine does not archive them, so surface them here), proxy scores vs floor, the gate verdict, promotions (or a clean no-promotion), the new board line.

## Don't get these wrong

- **Never score `--split final` for selection.** The final split exists to validate a promoted champion, once, before external claims. The engine firewalls those records out of sampling; don't route around it.
- **Never hand inventors the eval.** The brief is their whole context — do not add the adapter, the metric internals, or `archive/private/` to it. If an inventor edits a protected path, that candidate is dead regardless of its score.
- **Proxy deltas under the noise floor are noise.** Don't burn a full run on one, and don't celebrate one to the user.
- **The proxy screens, it never promotes.** A big proxy gain can invert at full budget. No win counts until it's re-scored at full and clears the pre-registered gates; commit the gates *before* scoring, never after seeing numbers.
- **G1 is sacred.** A candidate that improves the round objective (G2) but regresses primary fitness below the G1 floor is not a win. Report it as a trade-off finding, not a promotion.
- **Serialize resource-contended evals.** One scoring queue via tracked background tasks, not detached `&` (which loses tracking) and not long foreground commands (which time out).
- **Remote scoring** comes back via `evolve ingest --env <tag>`; scores compare only within one environment. Before trusting offloaded scores, run `evolve doctor --measure-env-offset` — it re-runs the champion in the new env and records the fitness offset, telling you whether the environments can be folded (offset within the noise floor) or must be partitioned via `fitness.selection_env`.

## Unattended rounds

`/loop <interval> /evolve:round` runs generations unattended. Keep the inner loop on proxy, promote sparingly, and let `evolve sample`'s exit-3 (budget/staleness) end the loop. Note exit 6 (infrastructure failure — export/dependency setup) is NOT a candidate failure and is not archived; retry rather than treating it as a dead candidate. Before claiming any improvement to the user, validate the champion once on the final split (if configured) with `evolve rescore --id <champion> --mode full --split final` and record the result as a neutral stat.
