# evolve:round — one generation

`evolve/EVOLVE.md` in the project is the manual; this skill is the entry point plus the decisions that are easy to get wrong. The `evolve` CLI (on PATH) is the decision-maker: parent selection, guards, dedup, budgets, and the final-split firewall are its calls, not yours — you orchestrate inventors and relay its verdicts.

## The round

1. **Re-ground.** `evolve board`; read `evolve/insights.md`. If `evolve sample` exits 3, the budget is spent or the search is stale — report and stop (this is the /loop stop condition; end the loop rather than overriding the engine). If the project runs with no budget block (or `"budget": {"disabled": true}`), exit 3 never fires — the stop condition is the owner's, so agree on one (rounds, spend, or a result) before looping unattended.
2. **Sample.** `evolve sample --k <N> --seed <round-tag>` — one slot per inventor: parent, operator (diff/rewrite/cross + partner), inspirations. The engine's weighted sampling deliberately does NOT always pick the top scorer; respect its choice — the offspring penalty is what keeps the search from tunnel-visioning one lineage, and each inventor's objective is its own parent, nothing else. The slot table is also persisted to `evolve/rounds/<seed>-<hash>-slots.json` (the exact path is printed as `slots_file`): that file is the round's evidence of what each inventor was ASSIGNED (distinct from what a candidate later claims as `--parent`), so never regenerate or edit it after dispatch.
3. **Brief + dispatch.** `evolve brief --operator <op> --parent <id> --seed <slot seed from sample> [--axis <axis>] [--cross-with <id>]` per slot — pass the slot's own `seed` (from `sample`'s output) so each inventor gets that slot's inspirations, and `--axis` is REQUIRED in registry mode. That context block is the inventor's whole grounding — pass it verbatim. Dispatch inventors as parallel subagents via the Workflow tool with `effort: 'high'` (effort is load-bearing: low-effort inventors produce safe tweaks that waste eval budget). Isolation is per-mode: markers mode uses `isolation: 'worktree'` so each inventor edits its own copy; registry mode builds a JAIL per slot — `evolve jail --parent <id> --axis <axis> --round <tag> --slot <n> --seed <slot seed> --operator <op> [--cross-with <id>]` (pass the slot's operator and partner — a cross slot without them gets a jail missing its partner's genome and impls, making the assigned operation impossible) — and launches the inventor with the jail as its cwd, where BRIEF.md (the information-diet brief: parent + baseline + score-free mechanism sources, leak-asserted before emitting) is its whole grounding. Without a jail, a registry inventor in the project cwd can read the archive and every doc, so the diet is theater (requires `surface.registry.inventor_files` — the measured harness closure — in the config). The inventor returns `PROPOSAL/<axis>__<impl>.py` + `PROPOSAL/hypothesis.txt`; pass the hypothesis to `evolve score --rationale`. If the Workflow tool is unavailable, fall back to sequential Agent-tool dispatch — same briefs, same rules. For genuine model diversity, external CLI inventors (run read-only, output captured) may be added on the identical brief. Require each inventor to return a structured proposal: name, one-line rationale, the risk it sees, and its edit (markers: edits in its worktree; registry: one complete impl module honoring the baseline's contract).
4. **Guard, then Reflexion.** Registry proposals: write each impl into `evolve/chunks/<axis>/` yourself and smoke-test the module in isolation before spending an eval (imports, obvious contract conformance) — inventors can't test against the live harness, so harden their integration bugs rather than discarding good ideas. All proposals: `evolve guard` first; on violation or a later dedup rejection (exit 4/5), re-brief the SAME inventor once with the engine's reason verbatim ("code outside markers changed"; "0.97 similar to X — differ mechanistically"), then drop the slot.
5. **Screen at proxy — the screen decides *spending*, not winning.** Per survivor, supply the candidate source — markers: `--candidate <worktree>` (its own worktree) or `--patch <file>`; registry: write the impl into `evolve/chunks/<axis>/` and pass `--genome <file>`. Full form: `evolve score --mode proxy --candidate <wt> --id <id> --parent <p> --inventor <who> --operator <op> --rationale "<one line>"`, serialized if the eval contends for resources. Spend a full run only on a candidate that beats its PARENT at proxy by more than the noise floor — child-vs-parent is the round's only comparison. **The proxy never concludes anything** — proxy→full can shrink *or invert* (a real search saw a proxy planning metric jump 0.011→0.286 that went 0/3 negative at full budget), and the direction isn't consistent across candidate families. Failures record with reasons — that is signal, not mess; never delete records.
6. **Trust only full budget.** Re-score each keeper at full: `evolve rescore --id <candidate> --mode full` (rescore replays the archived candidate under the new budget, reusing its id, so it never trips dedup). If the eval is noisy, first `evolve rescore --id <parent id> --mode proxy` back-to-back with the child and compare that *paired* delta — environment drift masquerades as fitness. Proxy→full can shrink or invert; report the full number as the candidate's result. There is no promotion or adoption step to clear: validity was already enforced per candidate (`eval.guardrails` at score time; a post-hoc discovery is an append-only retraction), and whether anything ships is an engineering decision outside the round (`evolve apply` materializes an artifact when someone wants it).
7. **Recombine.** After single-axis wins, stack them (registry: one genome carrying each axis's winner; markers: a cross-operator slot next round) and score the combination at full. Epistasis cuts both ways — the stack can beat or lose to its parts; test, never assume. Failed traits may be retried recombined in a changed context.
8. **Record + report — every round's result is its scored candidates.** Roughly every `search.insights_interval` generations (watch `board`'s generation count — there is no engine-side timer), distill the archive's recent records into `evolve/insights.md`: ≤5 recommendations, numbers not verdicts (editorializing biases the next round; negatives carry the same weight as wins). **A round with no new best is still a first-class result**: N scored candidates entered the archive, each measured against its parent, and that trade-off frontier (what moved, what didn't) is the round's deliverable — record it, don't treat it as a failed round. Report to the user: slots dispatched, guard/dedup rejections with reasons (these are session-local — the engine does not archive them, so surface them here), each child's score vs its parent and the noise floor, the new board line.

## Don't get these wrong

- **Never score `--split final` for selection.** The final split exists for one-shot, report-only validation of a candidate before any external claim. The engine firewalls those records out of sampling; don't route around it.
- **Never hand inventors the eval.** The brief is their whole context — do not add the adapter, the metric internals, or `archive/private/` to it. If an inventor edits a protected path, that candidate is dead regardless of its score.
- **Proxy deltas under the noise floor are noise.** Don't burn a full run on one, and don't celebrate one to the user.
- **The proxy screens, it never concludes.** A big proxy gain can invert at full budget. No number is a result until it's re-scored at full.
- **Serialize resource-contended evals.** One scoring queue via tracked background tasks, not detached `&` (which loses tracking) and not long foreground commands (which time out).
- **Remote scoring** comes back via `evolve ingest --env <tag>`; scores compare only within one environment. If an ingest is refused because the id is retracted, that is the engine preventing a wave from laundering a revoked candidate — reinstating is a deliberate act (`--reinstate`), not something a re-measurement does in passing. If a brief or jail build refuses because the slot's parent or partner was PRUNED mid-round, the remedy is to resample that slot (or the owner reinstates) — pruning never blocks scoring/ingesting the slot's already-dispatched children, only re-briefing. To revoke a candidate post hoc, use `evolve retract --id <c> --reason "<why>"` and verify by its effect on `board`. Before trusting offloaded scores, run `evolve doctor --measure-env-offset` — it re-runs the top-scoring record (or `--ref <id>`) in the new env and records the fitness offset, telling you whether the environments can be folded (offset within the noise floor) or must be partitioned via `fitness.selection_env`.

## Unattended rounds

`/loop <interval> /evolve:round` runs generations unattended. Keep the inner loop on proxy, re-score keepers at full, and let `evolve sample`'s exit-3 (budget/staleness) end the loop — on a project with no budget block or a disabled one, exit 3 never fires, so do NOT loop unattended without an owner-agreed stop condition. Note exit 6 (infrastructure failure — export/dependency setup) is NOT a candidate failure and is not archived; retry rather than treating it as a dead candidate. Before claiming any improvement to the user, validate that candidate once on the final split (if configured) with `evolve rescore --id <candidate> --mode full --split final` and record the result as a neutral stat — report it, never re-rank on it.
