The reader of a memory is a stranger: a future session with no access to the conversation where the lesson was learned, the project it came from, or the vocabulary of the system that stores it. Write so the stranger can act on a first read.

- **Lesson first, in plain words.** Open with the behavior itself, phrased the way a person would say it out loud. A methodology ("compare alternative hypotheses before concluding") is not the lesson; the habit it protects ("don't state a guess as a fact") is.
- **No system vocabulary in the body.** Terms that are load-bearing here mean nothing — or something else entirely — everywhere else. If a sentence needs another document to parse, rewrite it.
- **Patterns, not references.** Describe the failure's recurring shape in terms anyone can picture ("checked one place cursorily, found nothing, concluded it never happens"). Don't cite incidents, projects, or conversations the reader can't see; if an example needs its backstory, it doesn't belong.
- **Write for durability.** Specifics that drift — counts, versions, names — age into falsehoods; say "several", not a number that was true on the day of writing.

**How to apply:** Before saving, reread the body as the stranger: every sentence parseable, the failure picturable, the fix actionable — with nothing but the file itself? Revise until yes.
